1Overview & motivation

What the project is, and why the coordinate choice matters.

A piecewise-constant-curvature (PCC) model approximates a continuum soft arm as a chain of n segments, each bending along a constant-curvature arc. The classic PCC parameterization uses a curvature magnitude and a polar angle φ — which is undefined when a segment is straight, creating a kinematic singularity exactly at the most common operating pose.

This project follows the singularity-free, extensible formulation (see PCC_NominalModel.pdf): each segment is described by a bending vector plus axial extension,

q_i = [ θx_i , θy_i , ΔL_i ]   // regular at the straight pose — no polar φ

so an n-segment arm has generalized coordinate q ∈ R3n and is actuated by 3n chamber pressures P ∈ R3n. Every √(θx²+θy²) in the kinematics carries a small epsilon floor, so automatic-differentiation gradients stay finite at q = 0.

The controller does not act in joint space. Instead the dynamics are projected into Cartesian end-effector space — the state is just the tip position and velocity x_p = [p, ṗ] — and an acados MPC tracks a setpoint or trajectory there. The hidden, possibly redundant joint state is reconstructed on the fly by an inverse-kinematics closure.

Exactness by segment count. For n = 1 the Cartesian projection is algebraically exact, so the closed loop matches the true 3n-dof PCC plant to sub-millimetre. For n > 1 the redundant projection is approximate by construction; the residual is what a learned dynamics term (paper Sec. 7.4) is meant to absorb — out of scope for this nominal model.

4The model

From joint-space physics to a Cartesian end-effector ODE.

Joint-space dynamics (pcc_joint_model.py)

The true plant is a standard rigid-body-style equation of motion in the generalized coordinate, with elastic restoring and damping terms and pressure-driven actuation:

M(q) q¨ + C(q,q̇) q̇ + D q̇ + G(q) + K (q − q₀) = W P   // eqn 162

with full state x = [q, q̇] ∈ R6n and control u = P. M is the mass matrix (regularized by a small added modal inertia λ_M for conditioning), C Coriolis, D damping, G gravity, K the asymmetric bending/extension/compression stiffness, and W the constant pressure-to-generalized-force map. The term builder is shared with the Cartesian model so plant and controller never drift apart.

Kinematics (pcc_kinematics.py)

Smooth, Taylor-guarded shape functions give the per-segment homogeneous transform, the segment centre-of-mass positions, the forward map and its Jacobian:

p = h(q) ∈ R³   // tip position (eqns 27, 224) J_p = ∂h/∂q   // eqn 225

Cartesian projection (pcc_cartesian_model.py)

The controller’s state is only the end effector, x_p = [p, ṗ] ∈ R₆. The hidden joint state needed to evaluate the dynamics is reconstructed from p by an inverse-kinematics closure:

n = 1 closed form

Square, invertible FK with a derivative-smooth removable-singularity inverse (eqns 179–184) — no iteration, exact.

n > 1 damped IK

A fixed, unrolled damped-pseudoinverse + nullspace-prior iteration (K_IK steps, eqn 234) — bounded, smooth, no while-loop.

That gives the Cartesian-state right-hand side

ẋ_p = [ ṗ , f_PCC(p, ṗ, P ; q_prior, q̇_prior) ]   // eqn 248

where q_prior, q̇_prior are the reconstructed joint operating point carried between control steps.

Static feed-forward u_ref (make_static_uref_solver)

A redundant arm (n > 1) needs a reference input that holds the target at static equilibrium. We solve, once per step:

min​q ½ ∥u(q)∥² s.t. h(q) = p_ref, q ∈ Q, u(q) = W⁻¹(G(q)+e(q)) ∈ [P_min, P_max]

built once symbolically and solved with a CasADi nlpsol + IPOPT solver using dual warm-starting (the previous step’s multipliers lam_g/lam_x are reused), about 2× faster than the former SciPy SLSQP. The MPC then anchors its input at this equilibrium through the R_u∥u−u_ref∥² cost, which is what resolves the redundancy.

5The controller

A Cartesian-space acados OCP with two interchangeable prediction models.

The OCP is a NONLINEAR_LS tracking problem on the Cartesian output y = [p, ṗ, P] (stage) and y_e = [p, ṗ] (terminal):

J = Q_p∥p−p_ref∥² + Q_v∥ṗ−ṗ_ref∥² + R_u∥u−u_ref∥² + R_du∥u−u_prev∥² terminal: Q_p_e∥p−p_ref∥² + Q_v_e∥ṗ−ṗ_ref∥²

Prediction modes (--mpc-mode)

ltv — affine, fast

A per-step affine model θ = (A, B, c) rebuilt each step from the frozen IK operating point. The iterative IK never enters the QP sensitivities. PARTIAL_CONDENSING_HPIPM; hundreds of Hz.

nonlinear — true dynamics

The full projected dynamics with the IK re-solved inside the integrator RHS. Accurate but heavy. FULL_CONDENSING_HPIPM; single-digit Hz.

Solver options

Both modes use GAUSS_NEWTON Hessian, an IRK integrator, SQP_RTI (one QP per step), regularize_method = PROJECT, a raised QP-iteration budget, and warm starting.

Cost weights (config.MPC -- one shared set for all n)

Weight Value Role
Q_p / Q_p_e 5e4 / 1e5 position (stage / terminal)
Q_v / Q_v_e 5e3 / 5e3 velocity; caps tip speed → bounds cond(A)
R_u 1.0 anchor u at the static-equilibrium u_ref
R_du 1.0 input-rate penalty; smooths control under noise
N / t_horizon 30 / 1.0 s horizon

A single weight set is used for every n (no n=1 / n>1 split). R_u=1.0 anchors the input at the static-equilibrium u_ref: for n>1 it resolves the redundancy, and for n=1 (square, exact) it is the correct target too -- it even improves the n=1 settle. Q_v=5e3 caps tip velocity, which bounds the LTV model's conditioning. R_du=1.0 damps the per-step input change so the applied pressure stays smooth under measurement noise (~37% less step-to-step jitter at n=2 vs R_du=0).

Under the 1 mm measurement-noise default, n>1 circle tracking can hit a QP conditioning limit during the high-velocity start — use --meas-noise ≤ 0.0005 for n>1 on the closed curves. n=1 (all references) and n>1 setpoints are robust at 1 mm.

6Entry points

Everything is run from the repository root.

Closed-loop MPC — main.py 

python main.py --segments 2 --reference-type circle --mpc-mode ltv \
               --sim-time 10 --save-plot

Flags: --segments, --N, --t-horizon, --dt, --sim-time, --reference-type {setpoint,circle,pacman,star,lemniscate}, --mpc-mode {ltv,nonlinear}, --save-csv, --no-plot, --save-plot, --save-video, --meas-noise, --noise-seed, --solver-option {slsqp,vanilla,jit}, --rebuild (force a fresh build; cache reuse is on by default — see Build cache & Git LFS). By default main.py adds 1 mm white Gaussian sensor noise (--meas-noise 0.001) to p, ṗ to mimic a real robot: the controller/observer act on the noisy reading, while tracking error is evaluated against the noise-free ground truth. --meas-noise 0 runs fully deterministic.

Open-loop rollout — open_loop.py 

python open_loop.py --profile multisine --amp 0.25 --T 4 --n 2 --save-plot

Drives the true joint plant with an excitation profile and animates the backbone. Flags include --profile {multisine,step,ramp}, --const, --amp, --T, --dt, --n, --seed, --no-show, --save-data, --save-plot.

Benchmarks — benchmark/ 

python benchmark/controller_benchmark.py --segments 1,2,3 \
        --modes ltv,nonlinear --refs setpoint,circle,pacman,star,lemniscate
python benchmark/model_benchmark.py --profile multisine --n 2 --save

Tests — tests/ (run as modules)

python -m tests.sanity_checks       # fast, no acados build
python -m tests.verify_robustness   # closed-loop status gate
tests/verify_arm_spec.py is currently broken (it imports a TARGETS symbol no longer present in config.py); it is kept for reference only.

7Build cache & Git LFS

Reusing the compiled solvers, and sharing the large cache across machines.

The first run compiles the acados OCP/integrator to C under generated_c_codes/. Subsequent runs reuse those artifacts by default — and, with --solver-option jit, the JIT-compiled CasADi u_ref/linearization caches (cart_lin_n*.casadi, uref_ipopt_n*.casadi) — so repeat runs skip the cold build (which can be ~10 min). A short build-input hash next to each artifact auto-rebuilds it when --N/--t-horizon/--dt/--mpc-mode or config.PARAMS change; runtime args (reference, sim time, noise, I/O) are always reuse-safe. Pass --rebuild to force a fresh build — needed after editing model code, which the hash does not track.

The CasADi .casadi caches embed the compiled shared objects and are large — the n=3 linearization cache is ~150 MB. GitHub rejects any normal Git file over 100 MiB, so they are tracked with Git LFS: Git stores a small text pointer and LFS keeps the real binary, so clone/pull can still recover the cache.

A path can be LFS-tracked or .gitignored, not both. Do not ignore generated_c_codes/*.casadi if you want other machines to fetch the cache.

One-time setup (maintainer, to push the cache)

# install + enable Git LFS
sudo apt update && sudo apt install git-lfs -y
git lfs install

# track the CasADi caches with LFS (writes .gitattributes)
git lfs track "generated_c_codes/*.casadi"

# move already-staged .casadi out of normal Git and back in as LFS objects
git rm --cached generated_c_codes/*.casadi
git add .gitattributes generated_c_codes/*.casadi

# fold into the unpushed commit (or make a fresh one), then push
git commit --amend --no-edit
git lfs ls-files          # verify they are LFS-tracked
git push origin main

The key step is git rm --cached … && git add …: it drops the large files from normal Git and re-adds them as LFS objects.

Cloning on a new machine

sudo apt install git-lfs -y
git lfs install

git clone git@github.com:yu-mei/MetaMPC_BellowArm.git
cd MetaMPC_BellowArm
git lfs pull              # fetch the real .casadi binaries, not just pointers

For an existing clone, refresh with git pull && git lfs pull.

The caches are machine-specific binaries. Each .casadi embeds a compiled .so (and the acados *.so are native too) built for one CasADi/acados version + CPU arch + OS. On a machine that differs in any of those, the load raises RuntimeError and main.py logs [reuse-fail] … rebuilding, then rebuilds locally (safe, one-time) and overwrites the cache. So the LFS cache only transfers between machines with matching CasADi version (here 3.7.2), arch (x86_64) and OS (Linux); on a heterogeneous fleet prefer not committing the caches (gitignore generated_c_codes/*.casadi and build once per machine) to avoid cross-machine churn.
Keep LFS lean: every change to a binary cache file stores a new full version, so storage/bandwidth grow quickly if you commit them often — commit the cache only when the model/config actually changes. GitHub's per-file LFS limit is plan-dependent (≈2 GB Free/Pro, 4 GB Team, 5 GB Enterprise Cloud).

8Configuration

All knobs live in softarm/config.py.

Knob Controls
N_SEG Number of segments n (1 = exact path; >1 = redundant projected path).
REFERENCE type plus a per-n parameter dict for each shape.
PARAMS Geometry, mass, stiffness/damping, actuation gains, pressure limits, base frame, numerical & closure knobs.
MPC + mpc_for(n) cost weights and horizon (one shared set for every n).
SIM Control step dt and closed-loop duration T_sim.

The PARAMS values are calibrated to a hardware spec (rest length 0.077 m; uniform −90 kPa → 0.031 m; uniform +200 kPa → 0.099 m; two chambers +200 / one −90 → ~80° tip bend). Swap in system-identified values when available — nothing else needs to change.

9System identification

Calibrating the model's dynamics parameters from recorded hardware experiments.

softarm/sysid/ is an offline, single-segment calibration pipeline that fits the seven lumped dynamics parameters (paper eq 1544)

vartheta = [k_b, k_comp, k_ext, d_b, d_L, gamma_b, gamma_l]

— bending stiffness k_b, the sign-asymmetric axial stiffness k_comp (compression) / k_ext (extension), dampings d, and pressure-to-wrench gains gamma_b (bending) / gamma_l (axial). It is pure NumPy/SciPy, independent of the acados / MPC stack, and calibration-output only: it writes a JSON result and never modifies the model, W, or the controller. Because the gain γ and stiffness k are not separable from free-hanging tip data (gravity is too weak a force reference on a stiff arm — see the caveat), the pipeline follows the three decoupled stages of doc/main_improved.tex ("Practical Identifiability" / Stages 1–3).

CLI — python -m softarm.sysid.run_sysid 

# 0) (optional) synthesize CSVs from the model so the flow is testable
#    without hardware (rolls the plant for the Stage-2/3 recordings)
python -m softarm.sysid.run_sysid synth --out-dir softarm/sysid/data

# STAGE 1 -- actuation gains from BLOCKING-FORCE (isometric) tests
#   axial  : clamp tip (dL~0), sweep common-mode pressure +/-, record axial force
#   bending: hold straight, inflate/deflate one chamber +/-, record perpendicular
#            (cantilever) force; torque = L0 * F_perp
#   CSV columns (each): pressure_kPa, force_N  (both signed)
#   fits + compares split-linear (gamma^ext/gamma^comp) vs nonlinear h(sigma)
python -m softarm.sysid.run_sysid calibrate-gains \
    --axial   softarm/sysid/data/axial_block.csv \
    --bending softarm/sysid/data/bending_block.csv

# STAGE 2 -- stiffness from QUASI-STATIC tip data, gains known
#   solves  gamma*sigma - G(q) = k*q  (linear in k, no q-ddot)
#   CSV columns: time, base_x/y/z, tip_x/y/z, P1,P2,P3  (slow ramps)
python -m softarm.sysid.run_sysid fit-stiffness \
    --csv softarm/sysid/data/stage2_axial.csv softarm/sysid/data/stage2_bending.csv

# STAGE 3 -- damping from STEP responses, k and gamma known
#   trajectory matching: forward-sim with a trial d, minimise tip RMS
python -m softarm.sysid.run_sysid fit-damping \
    --bending-step softarm/sysid/data/stage3_bending_step.csv \
    --axial-step   softarm/sysid/data/stage3_axial_step.csv

Each stage appends to softarm/sysid/results/identified_params.json; load it later with load_identified_params / to_config_overrides from softarm.sysid (the latter flattens it into config.PARAMS-style keys). On real hardware, record the four CSVs in the column formats above and run the same three commands. The gain fit is reported both as a split-linear γ^ext/ γ^comp and as a nonlinear h(σ) so you can see which the hardware prefers.

Validate the whole pipeline end-to-end with python -m pytest tests/test_sysid_roundtrip.py — it generates synthetic data from the model and checks each stage round-trips (gains exact, stiffness <1%, d_b <2%).
Identifiability caveat (stiff arm) — why Stage 1 is a blocked-force test. From free-hanging tip data alone the gain γ and stiffness k are not separately identifiable — only their ratio (the compliance γ/k), because gravity is the only absolute force reference and on a stiff segment it is ~0.2–0.4% of the actuation/elastic forces (and the stiff axial q̈ is beyond mocap bandwidth, so the dynamic regression cannot recover the scale either). Stage 1 breaks the deadlock by measuring γ directly with a blocked-force bench test (configuration clamped, so elasticity, gravity, and inertia drop out); Stages 2–3 then use that γ as the missing reference.
